# Quality check 2026-11-01

The ten quality rules checked against the code, with evidence. Python venv, Windows 11. The engine
runs SQL over in-memory Arrow tables; DuckDB is used only as the reference in tests and the report.
It makes no network, database-server or subprocess calls.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | pass | No external calls. Errors are typed and surfaced: `BindError` for bad SQL (including parser errors and `RecursionError`), `ExecutionError` for unsafe plans; the CLI exits 2 on both. `except` clauses catch specific types only (`binder.py`, `executor.py`, `report.py`); no swallowed errors. |
| 2 | Writes safe to retry | N/A | The engine writes nothing (queries only). |
| 3 | No race conditions | N/A | Single-threaded Python; Arrow kernels run on immutable tables (`use_threads=False` in group-bys). |
| 4 | Don't trust the clock | pass | Timings use `time.perf_counter` (`report.best`, `cli.py`). Dates in the data are generated from a fixed start date and seed. |
| 5 | Read before changing | pass | APIs exist in the installed versions (mypy `--strict` with `pyarrow-stubs` clean). No environment variables are read. |
| 6 | Never break compatibility | pass | No stored formats. sqlglot is pinned to one major version and DuckDB below 2 (ADR 0002, pyproject). |
| 7 | One source of truth | pass | Table statistics (row counts, distinct values) are computed once at `Catalog.register` from the table they describe and replaced when a table is registered again. Python 3.11+ in pyproject and README; CI 3.12. |
| 8 | Small changes, no secrets, validate input | fixed | No secrets. SQL input is length- and depth-limited and bound with clear errors (`test_binder`). Found: `--scale nan` crashed with a `ValueError` and `--scale inf` tried to build infinite tables; `--repeat 0` crashed in `vqe-report`. Now refused by argparse with exit 2 (`test_a_scale_out_of_range_is_refused`, `test_report_refuses_bad_settings`). No new dependency. |
| 9 | Tests that can fail | fixed | No skips or tautologies. The DuckDB comparison catches wrong rows but not plans that reach the right rows a slower way; five mutants of that kind survived and now have targeted tests. 8 of 13 killed before, 13 of 13 after. |
| 10 | Re-verify | pass | `ruff`, `ruff format --check`, `mypy --strict`: clean; `pytest`: 289 passed; `pip-audit`: no known vulnerabilities. The CI result is recorded in the commit's workflow run. |
